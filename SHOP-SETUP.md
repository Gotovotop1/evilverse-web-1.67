# Магазин EVILVERSE: настройка, выдача, проверка

## Как всё устроено

```
Игрок → сайт (заказ) → оплата (Приват / USDT) → вы в /admin.html жмёте «Оплачено»
      → сервер Minecraft (плагин HellPrime) раз в 15 с сам забирает оплаченные заказы
      → выдаёт товары → сообщает сайту «выдано» → игрок видит статус в «Кабинете»
```

- Сайт передаёт серверу только **что куплено** (номер заказа, ник, товары). Какие команды выполнить,
  решает только `config.yml` плагина → взломанный сайт не сможет выполнить на сервере свою команду.
- Один заказ не выдаётся дважды: у сервера свой журнал выданных заказов.
- Если игрок ещё ни разу не заходил на сервер, заказ ждёт его первого входа (опечатка в нике не «сжигает» покупку).
- Старые оплаченные заказы (до этого обновления) автоматически помечаются «видано раніше (вручну)» и не выдаются повторно.

## 1. Переменные окружения в Vercel

Vercel → проект → **Settings → Environment Variables** (для Production и Preview):

| Переменная | Что это | Обязательно |
|---|---|---|
| `DATABASE_URL` | Postgres, на нём уже работают заказы | уже есть |
| `ADMIN_TOKEN` | пароль страницы `/admin.html` | да |
| `DELIVERY_TOKEN` | пароль, по которому сервер забирает заказы (тот же — в `config.yml` плагина) | да |
| `DISCORD_WEBHOOK_URL` | уведомления в Discord: новый заказ, «нужна ручная выдача», ошибки выдачи | по желанию |

Токены — длинные случайные строки (40+ символов, буквы и цифры), например из генератора паролей.
Никому не показывайте. После изменения переменных — **Redeploy**.

## 2. Обновление сайта

- Изменения лежат в ветке `claude/fishki-prime-delivery`. Vercel сам соберёт для неё **Preview**-сайт
  (ссылка будет в Vercel → Deployments и в GitHub у коммита).
- Проверьте превью (раздел 5), затем на GitHub: **Pull requests → New → base: main ← compare: claude/fishki-prime-delivery → Create → Merge**.
  После слияния Vercel выкатит изменения на основной сайт.
- База данных обновится сама при первом запросе: добавятся колонки выдачи, ничего не удаляется.

## 3. Сервер Minecraft (HellPrime)

1. Остановите сервер, замените `plugins/HellPrime-1.0.0.jar` новым.
2. Замените `plugins/HellPrime/config.yml`, `perks.yml`, `subscriptions.yml`, `gui.yml` файлами из архива
   (ваши файлы со всеми правками + новое). `data.db` и остальное не трогайте.
3. В `config.yml`, в самом конце, раздел `web-shop`:
   ```yaml
   web-shop:
     enabled: true
     url: "https://адрес-вашего-сайта"     # без / в конце
     token: "тот же DELIVERY_TOKEN, что в Vercel"
   ```
   Провайдер `payment.providers.shop` уже включён (валюта UAH) — через него выдаются подписки Prime.
4. Запустите сервер (не через PlugMan). В консоли не должно быть строк `Web shop: ...` с ошибками.

### Что выдаётся автоматически сейчас

| Товар на сайте | Что делает сервер |
|---|---|
| `prime`, `prime_plus` | подписка HellPrime на 30 дней (если уже есть — время добавляется) |
| `t100` … `t3000` | `p give <ник> <фишки + бонус>` |
| `unban`, `unmute` | `unban <ник>`, `unmute <ник>` (LiteBans) |
| привилегии, кейсы, цвет ника, префикс | пока **вручную**: заказ получает статус «частково — видати вручну» |

### Когда появятся привилегии и кейсы

Допишите команды в `config.yml → web-shop → items` и выполните `/primeadmin reload` (сайт менять не нужно):

```yaml
    demon: ["lp user {player} parent add demon"]                     # навсегда
    demon_30: ["lp user {player} parent addtemp demon 30d accumulate"]  # 30 дней
    c_xp: ["crazycrates give virtual XP {qty} {player}"]               # кейсы CrazyCrates
```

`{player}` — ник получателя (при подарке — друга), `{qty}` — количество, `{qty*N}` — количество × N, `{order}` — номер заказа.

## 4. Ежедневная работа

1. Приходит оплата (Приват/USDT) с кодом заказа в комментарии.
2. Откройте `https://ваш-сайт/admin.html`, введите `ADMIN_TOKEN`, фильтр «Очікують оплату».
3. Сверьте сумму и код → **✔ Оплачено**. Через ~15 секунд товар в игре.
4. Статусы выдачи:
   - **видано ✔** — всё выдано;
   - **частково — видати вручну** — автоматическая часть выдана, остальное (список «Видати вручну») — выдайте сами;
   - **помилка видачі** — раскройте «Журнал видачі», исправьте `config.yml`, `/primeadmin reload`,
     нажмите **↻ Повторити видачу** (уже выданное повторно не выдаётся).
5. Все выдачи также пишутся в `plugins/HellPrime/logs/operations-*.log` (строки `WEBSHOP`).

## 5. Как протестировать

**На Preview-сайте (до слияния в main):**
1. Откройте превью → магазин: вкладка **Prime** (две карточки), вкладка **Фішки** (красные монеты, «Разом: 330 фішок»).
   Переключите язык на RU/EN — тексты переведены.
2. `/admin.html` → введите `ADMIN_TOKEN` → открывается список заказов (старые оплаченные — «видано раніше (вручну)»).

**Полный цикл (лучше сначала на тестовом/своём аккаунте):**
1. На сайте закажите **«100 фішок»** на свой ник (способ оплаты любой, платить не нужно).
2. В `/admin.html` найдите заказ → **✔ Оплачено**.
3. В течение ~15 секунд в игре: `+100` фишек и сообщение «✔ Заказ EV-… с сайта выдан».
   В админке статус «видано ✔», в «Кабинете» сайта — «Оплачено · видано в грі».
4. Проверка защиты: нажмите на этом заказе «↻ Повторити видачу» → фишки второй раз **не** придут.
5. Prime: закажите **Prime** → «Оплачено» → в игре `/prime` показывает подписку на 30 дней.
6. Тестовые фишки заберите командой `p take <ник> 100`, тестовую подписку — `/pa remove <ник>`.

**Если не выдаётся:**
- в консоли сервера `сайт отклонил токен (401)` — `web-shop.token` ≠ `DELIVERY_TOKEN` в Vercel;
- `сайт ответил 503` — на сайте не задан `DELIVERY_TOKEN` (или не сделан Redeploy после добавления);
- заказ «оплачено», но не выдаётся и ошибок нет — игрок с таким ником ещё не заходил на сервер (заказ ждёт его входа);
- `PROVIDER_DISABLED` в журнале — включите `payment.providers.shop.enabled: true` в `config.yml`.

## 6. Безопасность

- `ADMIN_TOKEN` и `DELIVERY_TOKEN` — только в Vercel и в `config.yml` сервера. Если утекли — смените в обоих местах.
- Зависимости обновлены: Next.js 16.4.5, `pnpm audit --prod` — уязвимостей нет.
- Бесплатный тариф Vercel (Hobby) по правилам Vercel — для некоммерческих проектов; для приёма оплат нужен Pro
  или хостинг, где коммерция разрешена (Netlify, Cloudflare Pages).
